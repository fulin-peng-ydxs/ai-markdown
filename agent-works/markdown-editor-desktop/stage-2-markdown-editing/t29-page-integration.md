# T29 页面、原生菜单与文档状态集成

## 功能的详细需求

T29 对应 R1、R5、R11、R14、R30、R31，并承接 P1 7.1.1～7.1.7 与 P2 7.2.1～7.2.3 的第二阶段页面集成子集。目标是在既有单一 `DocumentSession`、两种编辑 adapter、保存控制器、恢复/冲突/另存和图片资源链之上，完成真实 P1/P2、平台原生菜单、持续状态栏、窄窗退化和无障碍状态的收口。

原生菜单只能启用当前聚焦窗口中已有真实消费者的命令。保存、另存、撤销/重做、当前文档查找和排版/源码模式必须进入与工具栏相同的 session、history 和保存通道；启动页、无文档、只读或处理中状态不得保留旧窗口的启用状态。剪切、复制、粘贴和全选继续采用平台原生编辑角色，不能再注册一套可能与系统加速键双触发的 React 全局快捷键。

底部状态栏必须持续显示当前文档的保存状态、编辑模式、字/字符数、编码、换行、光标或排版选择语义以及工作区可写性。它只能投影真实状态，不自行宣称磁盘成功；活动反馈可以进入 live-region，静态统计不得反复打断屏幕阅读器。1280、1050、820、740 px 与低高度窗口中，根页面不能出现额外滚动，窄窗应优先保留活动、保存和模式状态。

## 功能开发的实际结果

- Rust `menu.rs` 新增 `EditorMenuState` 与按窗口保存状态的 `EditorMenuStateRegistry`。状态包含是否有文档、只读、忙态、撤销/重做能力和当前模式；窗口聚焦时恢复自己的菜单状态，销毁时清理，启动页与无文档 P1 主动重置。
- 原生文件菜单启用保存 `Cmd/Ctrl+S` 与另存副本 `Cmd/Ctrl+Shift+S`；编辑菜单启用撤销、重做和当前文档查找 `Cmd/Ctrl+F`；显示菜单启用排版 `Cmd/Ctrl+Alt+1` 与源码 `Cmd/Ctrl+Alt+2`。前端消费者在执行前再次按当前菜单状态拒绝无文档、忙态、只读或不可用历史的晚到事件；未实现的工作区搜索、侧栏、页签、阅读和主题命令继续禁用。
- `DocumentEditorShell` 以受控 ref 暴露 `execute`、`focus` 和 `switchMode`，并上报编辑器运行 busy。原生菜单和工具栏因此消费同一命令与 session history，没有产生第二套正文、历史或保存状态。
- 新增 `DocumentStatusBar`。它复用 `SaveStatus`，展示真实模式、字/字符数、UTF-8、换行、源码行列或排版光标/选区语义及工作区可写性；只有活动反馈使用 live-region。820 px 以下隐藏次要统计，560 px 以下继续隐藏工作区说明，主要状态保持可见。
- P1 会把当前 session/readOnly/save busy/editor busy/mutation busy/history/mode 同步到 Rust；菜单事件只路由到聚焦窗口。P2 初始化时重置编辑菜单，避免从已打开文档的其他窗口继承错误启用态。
- 最新生产 `.app` 在 macOS 真实打开脱敏 `tests/fixtures/workspaces/basic/note.md`：启动页保存/另存禁用；无文档工作台显示“未打开文档”；打开文档后保存、另存、查找和模式命令启用，撤销/重做按空历史禁用；从原生“显示”菜单切换源码后，编辑器和状态栏共同变为源码模式并显示 `12 字/词 · 84 字符 · UTF-8 · LF · 行 1，列 2`。本次只切换内存模式，没有修改 fixture 正文。

## 功能开发的具体实施方案

1. TypeScript 与 Rust 共同定义工作台菜单动作和 `EditorMenuState`。Rust parity 测试锁定字段名、模式枚举和动作值，避免两端手工契约漂移。
2. P1 从当前 session 派生菜单状态，通过 Tauri 命令写入当前窗口注册表；Rust 只对聚焦窗口应用状态。窗口 focus 事件恢复对应记录，destroy 事件删除记录，避免多窗口共享平台菜单时由后台窗口覆盖前台。
3. 保存事件调用既有手动保存控制器；冲突先进入已有冲突流程；另存进入已有 `SaveCopyDialog`；撤销/重做/查找/模式切换通过 `DocumentEditorShell` handle 进入与工具栏相同的命令总线。
4. 系统剪贴板角色由 Tauri predefined menu item 承载，直接作用于当前聚焦的 CodeMirror/ProseMirror 控件，不通过自定义事件重复派发。
5. `DocumentStatusBar` 只接收 session、工作区和页面活动的只读投影。源码行列按 raw Markdown 选择偏移计算；排版模式不伪造字符级位置，只显示“排版光标”或“排版选区”。
6. 浏览器临时入口验证 1280/1050/820/740 px 和 740×460；820 px 以下文件树切换抽屉，打开后焦点进入关闭按钮，编辑器保留内部滚动。验证结束后删除临时入口并停止开发服务。
7. 最新前端产物先以 Vite 构建，再使用 Tauri 直接打包 `.app`；真实应用验收通过辅助功能树检查 P2、P1、状态栏和文件/编辑/显示菜单，避免误用旧 bundle。

## 复用判断

- `DocumentStatusBar` 复用 `SaveStatus`，没有复制 `DocumentSaveState` 到文案/色彩的映射。工具栏的紧凑状态用于局部编辑上下文，底部状态栏用于持续窗口状态，两者职责不同但共享同一基础组件。
- 原生菜单和工具栏复用 `DocumentEditorShell` 的同一命令总线；没有为菜单另建保存控制器、撤销栈、查找状态或模式状态。
- 多窗口菜单需要平台全局菜单与窗口局部 session 之间的稳定协调，故在 Rust 建立轻量 `EditorMenuStateRegistry`；它只保存可见菜单投影，不持久化正文或偏好。
- 现有 `AppDialog`、`AsyncStatePanel`、`focusContainment`、`plainroot-button`、`tokens.css` 和页面壳继续原样消费。本任务没有出现第二处新的同职责对话框、状态面板或路径代数，无需额外抽取。
- P1 与 P2 的 gateway 保持页面职责分离，但两者都消费同一 `resetEditorMenuState` 桌面服务；没有复制 Tauri invoke 名或错误映射。
