# Plainroot Markdown 桌面编辑器需求闭环分析

> 产品名称：Plainroot  
> 闭环状态：本整改版本待外部复核确认；上一轮外部复审已确认主体闭环可进入开发计划<br>
> 目标平台：Windows + macOS  
> 品牌表达：A calm, local-first Markdown editor. Write clearly. Keep it yours.

## 1. 需求理解

Plainroot 是一款本地优先的桌面 Markdown 查看与编辑工具。产品以真实 `.md` 文件为内容事实源，以 Obsidian 式克制工作台、安静的中性色和适合长期通读的排版为视觉基础，同时保留所见即所得与 Markdown 源码两种编辑路径。

本轮确认将产品从“单文档三栏页面”升级为完整桌面工作台：

- 一个本地目录对应一个原生应用窗口。
- 一个窗口内可用多个真实文档页签并行编辑，不以替换唯一文档模拟切换。
- 打开其他目录时明确选择在当前窗口替换、在新窗口打开或取消。
- 使用操作系统原生窗口控制，不完全自绘桌面窗口框架。
- 当前颜色规则固化为内置 `Plainroot Neutral`，同时提供可新增、复制和编辑的颜色预设模块及实时预览。
- 自定义预设库全局共享，当前预设和窗口布局按工作区保存。

产品参考 Obsidian 的信息架构、密度、排版和配色，不复制其闭源核心应用源码、品牌资产、插件体系或与基础编辑、查看无关的复杂功能。

## 2. 业务目标

1. 让用户从启动页选择真实目录后，在原生桌面窗口内完成多文档查看、编辑、保存和恢复。
2. 让多页签和多窗口具有清晰、可靠的文档生命周期，关闭、替换目录和退出时不静默丢失内容。
3. 让所见即所得和源码编辑共享同一 Markdown 内容源，复杂语法可以保留和修复。
4. 让文件树、活动页签、编辑器、大纲、状态栏和窗口标题始终指向同一文档。
5. 让默认视觉保持中性、清楚且不疲劳，同时允许用户在安全的语义令牌范围内形成自己的颜色皮肤。
6. 在窗口、侧栏和显示器变化时保持正文重排、编辑状态和阅读锚点稳定。
7. 所有核心能力离线成立，不依赖账号、云同步、插件市场或私有内容数据库。

## 3. 用户角色与主要场景

### 3.1 用户角色

首版只有本机用户：

- 可选择操作系统允许访问的文件或目录。
- 对可写文件执行查看、编辑、保存和目录管理。
- 对只读文件执行查看、复制、大纲导航和阅读，不展示虚假保存成功。
- 可维护本机全局颜色预设库和工作区级显示偏好。
- 不建立账号、组织、成员或在线权限体系。

### 3.2 主要使用场景

- 开发者同时打开 README、设计文档和变更记录，在页签间频繁切换并保留各自光标和撤销栈。
- 写作者在所见即所得模式写作，需要时切换 Markdown 源码处理复杂结构。
- 阅读者进入分页阅读，在固定窗口内翻页并通过大纲保持长文上下文。
- 用户同时打开多个不同目录，每个目录使用独立窗口、页签集合、布局和搜索范围。
- 用户打开另一个目录时，选择替换当前窗口或保留当前工作区并新建窗口。
- 用户复制默认颜色预设，调整正文、界面和强调色，实时预览并保存为自己的皮肤。
- 外部工具修改当前文件，Plainroot 暂停自动覆盖并提供明确冲突处理。

## 4. 完整业务闭环

### 4.1 主链路

1. 用户启动 Plainroot。
2. 应用展示最近工作区、“打开文件夹”和“打开 Markdown 文件”。
3. 用户选择目录；应用获取系统授权并检查该目录是否已在其他窗口打开。
4. 若已打开，聚焦原窗口；否则在当前空窗口载入目录，或按用户选择创建新原生窗口。
5. 应用扫描工作区、恢复窗口布局、页签顺序、活动页签和内容锚点。
6. 用户从文件树或搜索结果打开文档；同一路径已有页签时聚焦已有页签，否则创建新页签。
7. 活动页签驱动中央编辑器、当前文件选择、文档大纲、状态栏和窗口标题。
8. 用户在排版编辑、Markdown 源码和阅读模式间切换；模式共享同一内容源并保留语义位置。
9. 内容变化进入已修改状态，防抖后安全写入真实 `.md` 文件，并同步大纲、字数和搜索索引任务。
10. 用户关闭页签、关闭窗口、替换工作区或退出应用前，系统处理全部保存失败、只读和冲突状态。
11. 应用保存各窗口的目录、位置、尺寸、布局、页签和活动文档；异常退出时额外保存恢复快照。
12. 下次启动逐窗口恢复；路径失效或权限撤销时，单独要求重新授权或移除，不阻塞其他窗口。

### 4.2 页签支链路

1. 用户点击文件树、搜索结果或最近关闭文档。
2. 系统按绝对路径检查当前窗口是否已存在页签。
3. 已存在则聚焦并恢复其光标、滚动和模式；不存在则创建加载中页签。
4. 读取成功后建立独立文档会话；读取失败保留路径、错误和重试入口。
5. 用户可切换、拖动排序、关闭、关闭其他、关闭右侧和关闭全部。
6. 关闭阻塞页签时提供重试保存、另存、放弃或保持打开；取消关闭保持全部状态。
7. 成功关闭后加入最近关闭列表；重新打开恢复路径和尽可能接近的内容锚点。

首版不实现预览页签、固定页签和跨窗口拖拽页签，避免基础生命周期中出现隐式替换或跨工作区移动歧义。

### 4.3 多窗口支链路

1. 当前窗口已有工作区时，用户执行“打开文件夹”。
2. 系统目录选择器返回目标目录。
3. 若目录已在其他窗口打开，聚焦已有窗口并结束流程。
4. 否则展示“当前窗口打开”“新窗口打开”“取消”。
5. 选择当前窗口：检查当前全部页签，解决阻塞保存状态后替换工作区；任何未解决项都中止替换。
6. 选择新窗口：创建独立原生窗口并载入目标目录，原窗口保持不变。
7. 用户可以记住“每次询问 / 当前窗口 / 新窗口”偏好，并在设置中重置。
8. 关闭单个窗口只结束该工作区会话；退出应用才统一处理全部窗口。

### 4.4 颜色预设支链路

1. 用户进入“设置 > 外观 > 颜色预设”。
2. 左侧预设库展示只读 `Plainroot Neutral` 和用户自定义预设。
3. 用户复制内置预设或新建预设，并为明亮、暗色两组语义令牌设置颜色。
4. 每次修改只实时预览当前窗口与示例文档，其他窗口不受草稿影响。
5. 按整改期补充的非阻塞推断，系统持续校验名称唯一性，以及明亮、暗色两套调色板的颜色格式和文字对比度；任一套不通过都不能保存。该联合阻断规则仍需在主题开发计划阶段确认，不能回写成用户既有决定。
6. 校验通过后保存到全局预设库，并通知正在使用该预设的窗口更新。
7. 用户取消、按 Esc 或放弃关闭时，当前窗口完整恢复进入工作室前的预设和值。
8. 删除使用中的自定义预设前必须指定回退预设；内置预设不可删除。

颜色皮肤只改变应用与阅读渲染，不向 Markdown 写入颜色、HTML 或私有元数据。字体、字号、行高和正文宽度继续由独立排版设置管理。

### 4.5 文件与资源支链路

- 新建、重命名、移动和删除文件后，磁盘状态成功才更新文件树和页签路径。
- 删除优先进入系统废纸篓/回收站；无法使用时二次确认永久删除。
- 粘贴或拖入图片时写入工作区资源目录并生成相对链接；重名不覆盖。
- 外部删除当前文件时保留恢复副本，允许另存或关闭。
- 解析失败保留原始文本，并允许直接进入源码模式处理。

### 4.6 布局、阅读与搜索支链路

- 左侧文件树、中央文档和右侧大纲支持横向拖动调宽；中央区域始终优先保留。
- 窄窗口先把大纲、再把文件树退化为抽屉，不覆盖工作区保存的理想宽度。
- 阅读模式按当前容器重新分页，以标题或段落锚点恢复位置，而不是依赖旧页码。
- 搜索只覆盖当前窗口绑定的工作区；点击结果打开或聚焦目标页签并定位片段。
- 索引损坏可重建，不能阻塞正文读取和保存。

### 4.7 状态流转

#### 应用与窗口状态

`无窗口 → 启动窗口 → 工作区加载中 → 工作区可用 → 保存检查中 → 已关闭`

异常分支：

- 路径失效：`加载中 → 重新授权/移除记录`。
- 同目录已打开：`选择目录 → 聚焦已有窗口`。
- 新窗口失败：`创建中 → 失败 → 重试/留在当前窗口`。
- 恢复失败：单个窗口进入恢复提示，其他窗口继续恢复。

#### 页签状态

`加载中 → 干净 → 已修改 → 保存中 → 已保存`

异常分支：

- `保存中 → 保存失败 → 重试/另存/保持打开`。
- `干净或已修改 → 外部冲突 → 重新加载/覆盖确认/另存`。
- `任意可见状态 → 只读 → 另存副本或继续查看`。
- `阻塞状态 → 请求关闭 → 解决/取消关闭`。

#### 主题预设状态

`已保存预设 → 草稿预览 → 校验通过 → 保存中 → 已保存并广播`

异常分支：

- `草稿预览 → 格式或对比度错误 → 继续调整`。
- `草稿预览 → 取消/放弃 → 原子回退`。
- `保存中 → 失败 → 保留草稿并重试`。
- `预设损坏/缺失 → Plainroot Neutral`。

#### 展示模式

`排版编辑 ⇄ Markdown 源码 ⇄ 分页阅读`

三种模式共享同一 Markdown 内容源，切换前提交当前编辑器状态并保持语义锚点。专注是窗口布局状态，不产生第二份内容。

| 主题预设工作室 | 创建个人颜色皮肤 | 新建、复制、编辑、删除、预览 | 草稿、校验、保存、回退 | 全局库、工作区选择 | 对比不足阻止保存 |
| 自适应布局 | 调整三栏空间 | 拖动、键盘调宽、复位、收起 | 宽度反馈、正文重排 | 按工作区保存 | 越界夹取，损坏回退 |

## 6. 页面闭环

### 6.1 工作区启动与最近目录

- 页面职责：首次启动、新建窗口和无工作区状态下承接打开入口。
- 核心内容：Plainroot 品牌、打开文件夹、打开 Markdown 文件、最近工作区。
- 关键状态：最近为空、路径失效、权限不足、恢复失败和打开中。
- 输出消费：成功选择的目录交给窗口管理与工作区加载模块。
- 原型：`prototypes/workspace-launcher.html`。

### 6.2 Markdown 多页签工作台

- 页面职责：承载原生窗口、真实页签、三栏布局、编辑、阅读、搜索和状态反馈。
- 层级：原生标题与菜单 → 文档页签 → 文档工具 → 三栏工作区 → 状态栏。
- 活动页签是当前文件、大纲、状态栏和窗口标题的唯一来源。
- 主题和布局重置等低频命令进入设置或更多菜单，不与高频文档命令竞争。
- 打开其他目录时在当前工作台之上展示明确决策对话框。
- 原型：`prototypes/markdown-workbench.html`。

### 6.3 颜色主题预设工作室

- 页面职责：管理内置和自定义颜色预设，并实时预览语义令牌。
- 层级：预设库 → 明亮/暗色令牌编辑器 → 实时文档预览 → 固定保存/取消区。
- 内置预设只读；复制后才允许修改。
- 错误紧邻颜色字段显示，并同步显示色值、色块和对比度，不能只靠颜色说明。
- 原型：`prototypes/theme-preset-studio.html`。

### 6.4 工作区打开决策对话框

- 入口：当前窗口已有目录时再次打开其他目录。
- 主要操作：“新窗口打开”；次要操作：“当前窗口打开”；安全退出：“取消”。
- 当前窗口存在阻塞页签时先进入保存检查，不能先清空界面。
- 可记住选择，并在设置中恢复每次询问。

### 6.5 冲突与关闭保护对话框

- 展示文件路径、磁盘修改时间、当前页签状态和内容是否仍安全。
- 冲突操作：重新加载磁盘版本、覆盖确认、另存副本、取消。
- 关闭保护：重试保存、另存、放弃修改、保持打开。
- 破坏性操作必须写明结果，不使用模糊“确定”。

## 7. 已确认关键决策

| 决策 | 确认结果 | 设计影响 |
| --- | --- | --- |
| 工作区与窗口关系 | 一个目录对应一个窗口 | 文件树、搜索、布局和会话均按窗口隔离 |
| 打开其他目录 | 当前窗口 / 新窗口 / 取消 | 当前窗口替换前执行全部页签保存检查 |
| 同目录重复打开 | 聚焦已有窗口 | 首版不产生重复写入会话 |
| 窗口框架 | 使用系统原生窗口控制 | 原型展示 macOS 变体，需求同时覆盖 Windows |
| 文档切换 | 真实多页签 | 不使用单文档内容替换模拟页签 |
| 颜色默认 | 保留当前中性预设 | 命名为 `Plainroot Neutral` 并作为安全回退 |
| 颜色自定义 | 全局自定义预设库 | 内置只读，可复制、新建、编辑和删除 |
| 预设选择 | 按工作区保存 | 不同目录可使用不同皮肤 |
| 实时预览 | 仅当前窗口草稿预览 | 保存后才同步其他消费窗口，取消完整回退 |

## 8. 非阻塞默认决策

- 首版页签支持排序、关闭菜单、溢出列表和最近关闭，不做预览页签、固定页签和跨窗口拖拽。
- macOS 原型使用红黄绿系统控制；Windows 实现改用右侧最小化、最大化/还原、关闭及平台菜单，不机械复制 macOS 外观。
- 主题预设开放稳定语义令牌，Hover、选区、代码背景和禁用态由系统推导，避免配置项爆炸。
- 普通正文对纸面最低对比度 `4.5:1`，大标题最低 `3:1`；不满足时允许预览但不能保存。
- 明亮、暗色两套调色板必须联合通过后才能保存，是整改期为避免未预览调色板损坏而补充的非阻塞推断；主题状态机开发前确认，确认前不得表述为上游已决定。
- 一个窗口关闭不退出其他窗口；应用退出才统一处理所有会话。
- 窗口与页签恢复失败只影响对应工作区，不阻塞其他窗口进入可用状态。
- `17 px / 1.76`、`760～820 px` 正文行宽和 `252/220 px` 侧栏宽度是当前原型的非阻塞推断默认值，不是用户已确认的固定数值；用户确认的是“中性但不过淡、长期阅读不疲劳”以及可拖动、自适应的方向。

## 10. 推断依据与约束

- “参考 Obsidian”解释为吸收其工作台信息架构、中性密度与长文排版，自主实现 Plainroot，不复制核心源码和品牌资产。
- “像 IDEA 的多窗口”解释为目录级窗口：一个目录一个窗口，打开其他目录选择当前或新窗口。
- “多页签”解释为每个文档拥有独立会话状态，而不是更新同一个编辑器容器的文件名与内容。
- “颜色皮肤预设”解释为应用与阅读渲染的语义颜色系统，不改变 Markdown 内容，也不与字体排版配置混合。
- “实时预览”解释为草稿只影响当前窗口；保存前不能污染其他窗口或已保存预设。
- R24 保留上游“固定页签与预览页签”组合表述的追溯关系，不直接进入开发或验收；原子能力分别由 R33、R34 承接。
- “PC 端窗口”解释为 Windows 与 macOS 桌面应用，并按平台使用原生控制、菜单、快捷键、全屏和窗口恢复。
- 页面整体和各区域可拖动继续解释为操作系统窗口可缩放、三栏主工作区可横向调宽；标题栏、页签栏和状态栏保持稳定高度。
- 正式需求中的 Tauri、React、Milkdown/ProseMirror、CodeMirror、SQLite/FTS5 仅是基于上述约束形成的推断候选，不属于本闭环已确认事实；依赖锁定前必须验证并记录结论。

## 11. 开发前高风险项

1. Markdown 所见即所得与源码模式之间的无损往返模型。
2. 多页签下独立撤销栈、保存状态、关闭保护和活动文档一致性。
3. 多窗口创建、聚焦、退出、异常恢复和同目录去重。
4. 当前窗口替换目录时对全部页签执行可取消的保存检查。
5. 主题草稿的窗口级隔离、保存后的跨窗口广播和取消原子回退。
6. 分页阅读在宽度、主题和字体变化后的重排与语义锚点恢复。
7. 文件监听、自身写入去重和外部冲突状态机。

这些模块需要在开发计划中单独设计状态机和故障注入测试，不能只按页面按钮拆分任务。
