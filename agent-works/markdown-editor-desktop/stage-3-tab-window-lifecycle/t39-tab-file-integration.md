# T39 页签打开、最近关闭与路径影响分析留痕

## 1. 任务与范围

- 任务：T39 打开去重、最近关闭与路径影响分析。
- 对应需求：R2、R3、R6、R11、R13、R30 的第三阶段子集。
- 入口：P1 文件树、初始文档、页签溢出菜单，以及文件/目录重命名、移动、删除的提交前检查。
- 本任务不实现 T40 的批量结算、磁盘成功后的多 runtime 原子重映射，也不实现 T42 的已有窗口会话启动恢复。

## 2. 实际交付

### 2.1 最近关闭与统一重开

- `WorkspaceTabManager` 以统一 `open()` 重新打开最近关闭项，重新消费 Rust 返回的规范化相对路径和 opaque 路径身份，不信任已保存路径文本。
- 重开成功后恢复仍兼容的模式、选择与锚点，并从最近列表移除；路径失效或无权限时保留记录和稳定错误，可显式移除元数据。
- 移除最近记录只改变应用元数据，不删除 Markdown 文件。
- `WorkspaceTabBar`、`TabOverflowMenu` 继续复用共享 `TabMenu` 的 menu 语义、方向键、Esc 和焦点返回，不新增平行菜单体系。

### 2.2 当前会话元数据持久化

- `tabSessionProjection.ts` 将当前有序页签、活动项、轻量视图与最近关闭投影为 `WindowTabSessionSnapshot`，不包含 Markdown 正文、history 或恢复正文。
- `WorkspaceTabSessionPersistence` 先读取 Rust 仓储，以 180 ms 防抖和 revision/CAS 保存当前会话；保存期间出现新变更会排队下一次写入，只有真正提交的 collection revision 被标记为持久化。
- 读取或写入失败后停止本轮自动写入并向 P1 报告真实错误，不循环重试或宣称成功。
- 若仓储已有非空会话，T39 不覆盖尚未恢复的页签元数据。该状态等待 T42 先恢复轻量 descriptor、惰性加载活动页签，再接管后续写入。

### 2.3 路径影响分析与安全边界

- `tabPathImpact.ts` 以不可变输入分析 rename/move/delete，收集全部受影响打开页签及提交后的相对路径。
- 对所有已加载文档计算内联 Markdown 图片链接改写预案；不扫描或虚构未打开文档引用。
- T40 尚未建立两阶段结算及批量 runtime 提交时，只要操作命中任一打开页签或需改写其内容，P1 就在调用 Rust 磁盘命令前阻止操作并给出明确原因。
- 没有页签影响的文件操作仍沿用既有磁盘先行链路；任何失败都保持文件树、页签和文档内容不变。

## 3. 复用与设计判断

- 复用 `WorkspaceTabManager`、`TabMenu`、`workspacePath`、`workspaceAssetPath`、现有 Rust window-session gateway 和公共错误文案。
- 新增 `tabPathImpact` 是纯路径/引用影响原语；新增 `WorkspaceTabSessionPersistence` 只承担会话元数据写入调度。两者变化原因不同，不合并进页面组件或单文档保存控制器。
- 页面只扩展既有溢出菜单分区，样式全部消费现有语义 token；没有新增页面、颜色、对话框、根滚动或私有状态优先级。
