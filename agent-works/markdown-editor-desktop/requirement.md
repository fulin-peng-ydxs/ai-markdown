# Plainroot Markdown 桌面编辑器需求文档

> 产品名称：Plainroot  
> 文档状态：需求已确认，可进入开发计划  
> 目标平台：Windows + macOS  
> 品牌表达：A calm, local-first Markdown editor. Write clearly. Keep it yours.  
> 产品定位：本地优先的 Markdown 查看与编辑工具，以 Obsidian 式克制工作台和长文阅读排版为视觉基础，保留所见即所得编辑能力，不复制其源码或扩展生态。

## 1. 背景与目标

### 1.1 背景

用户需要一款面向桌面的 Markdown 文档工具，既保留 Markdown 文件开放、便于迁移的特点，又提供接近传统排版软件的查看与编辑体验。产品不以知识图谱、插件市场或多人协作为首要方向，而以“打开本地目录后即可舒适写作和阅读”为核心。

### 1.2 已确认目标

- 首发提供 Windows 与 macOS 桌面应用。
- 支持本地 Markdown 文件夹、文档文件目录和当前文档标题大纲。
- 提供所见即所得编辑体验，并保留 Markdown 源码模式。
- 以 Obsidian 的工作台密度、信息层级和中性配色为参考，建立适合长期通读的低刺激视觉系统。
- 普通正文和标题以中性色为主，单一低饱和紫灰只用于选中、链接、键盘焦点和当前大纲项；状态色仅在对应状态出现。
- 页面整体随桌面窗口尺寸变化而自适应；主工作区各区域可拖动调整宽度，正文内容随可用宽度实时重排。
- 编辑模式采用中央画布受控滚动；阅读模式采用无纵向滚动条的分页阅读。
- 一个工作区目录对应一个原生窗口；一个窗口内通过多个真实文档页签承载并行编辑。
- 打开其他目录时明确选择在当前窗口替换或在新窗口打开，并保护当前窗口全部页签的保存状态。
- 当前中性颜色规则作为内置 `Plainroot Neutral` 预设，同时支持新增、复制和编辑自定义颜色预设并实时预览。
- Markdown 文件是内容唯一事实源，不以私有数据库格式替代原文件。

### 1.3 成功结果

用户能够从启动页打开一个或多个本地目录，在独立原生窗口内以多页签并行查看和编辑文档，完成目录管理、大纲导航、保存、冲突处理、主题预设编辑和分页阅读，并在再次启动应用时恢复各窗口、页签、布局与阅读位置。

## 2. 当前项目现状

- 当前为绿地项目，工作区中未发现可复用的业务代码、数据库结构、设计系统、组件库或既有页面。
- 当前没有可用于校准的 `DESIGN.md`、应用路由、文件模型、权限模型或测试基线。
- 本文档继承并展开已确认的上游“需求闭环分析”；用户已确认桌面端形态、Windows + macOS 平台和编辑/阅读滚动策略。
- 用户新增并确认：窗口整体和主工作区各区域必须支持宽度调整，内容必须自适应。
- 用户新增并确认：视觉以 Obsidian 的排版与中性配色为参考，首版只承载基础编辑、查看和导航，不使用高亮度多色装饰，也不直接复制 Obsidian 核心应用源码。
- 用户新增并确认：一目录一窗口、一个窗口内多文档页签；打开其他目录时提供“当前窗口 / 新窗口 / 取消”。
- 用户新增并确认：使用操作系统原生窗口控制，不使用完全自绘窗口框架。
- 用户新增并确认：内置颜色预设只读，自定义预设全局共享，当前预设按工作区保存并支持实时预览。
- 本文档附带三个交互原型：`prototypes/markdown-workbench.html`、`prototypes/workspace-launcher.html`、`prototypes/theme-preset-studio.html`。

### 2.1 推荐技术基线

本节作为开发计划的建议依据，不替代后续依赖评估：

- 桌面壳：Tauri 2，使用系统 WebView 承载界面并提供受权限范围约束的本地文件能力。
- 前端：React + TypeScript。
- Markdown 所见即所得编辑：Milkdown/ProseMirror。
- Markdown 源码模式：CodeMirror 6。
- 文件内容：工作区中的真实 `.md` 文件。
- 本地辅助数据：应用数据目录中的 SQLite 或等价轻量存储，仅保存索引、最近记录、布局偏好和恢复快照。
- 搜索：首版按工作区规模选择增量扫描或 SQLite FTS5；索引损坏时必须能够从 Markdown 文件重建。

## 3. 用户角色与使用场景

### 3.1 用户角色

首版只有“本机用户”一个角色：

- 可选择本机有权访问的文件或文件夹。
- 对可写文件执行查看、编辑、保存、重命名、移动和删除操作。
- 对只读文件仅查看和复制，不显示虚假的保存成功状态。
- 不建立账号、组织、成员或在线权限体系。

### 3.2 典型场景

1. 开发者打开包含多份 Markdown 文档的项目目录，通过文件树和大纲定位章节并修改说明。
2. 内容创作者新建文章，在所见即所得模式中写作、插入图片、引用、代码块和提示块。
3. 阅读者进入分页阅读模式，在固定窗口内使用方向键、空格键或滚轮翻页，不面对长纵向滚动条。
4. 用户拖动左、右分隔条调整文件目录、正文画布和文档大纲宽度，正文立即换行并保持当前编辑位置。
5. 外部程序修改了当前文件，应用检测到冲突并让用户选择重新加载、保留当前版本或另存副本。
6. 用户在同一窗口打开多个 Markdown 文档，以页签切换、排序、关闭和恢复最近关闭文档。
7. 用户打开另一个目录，选择替换当前窗口或创建新窗口；多个窗口分别恢复自己的目录、页签和布局。
8. 用户复制 `Plainroot Neutral` 创建自定义颜色预设，在当前窗口实时预览后保存并应用。

## 5. 详细功能需求

### 5.1 R1：桌面应用与本地工作区

- 前置条件：用户已安装应用，并对目标文件或目录拥有系统访问权限。
- 操作流程：启动应用后可选择“打开文件夹”“打开 Markdown 文件”或最近工作区；首次进入没有默认读取任意用户目录的权限。
- 窗口框架：使用操作系统原生窗口控制和能力；macOS 使用系统红黄绿控制与全局应用菜单，Windows 使用最小化、最大化/还原、关闭控制及平台菜单惯例。
- 标题栏支持拖动、双击最大化/还原、全屏、系统贴靠和高 DPI 显示；标题按“工作区 — 当前文件 — Plainroot”表达，不伪装成浏览器标签页。
- 桌面菜单至少包含“文件、编辑、显示、窗口、帮助”或系统语言对应名称；常用命令同时提供当前平台快捷键，低频设置不长期占据文档工具栏。
- 输入：用户通过系统选择器确认的文件或目录路径。
- 输出：工作区文件树、最近工作区记录、当前打开文档。
- 校验规则：仅在用户授权范围内读写；符号链接、不可访问目录和路径失效必须明确反馈。
- 异常情况：目录不存在、权限被撤销、文件被占用时不导致应用崩溃，提供重试或重新选择入口。
- 权限与数据范围：仅本机用户当前授权的路径。
- 对现有功能影响：无既有功能；该能力是所有内容功能的前置。

### 5.2 R2：文件与文件夹目录管理

- 文件树仅展示工作区内文件夹和受支持的 Markdown 文件；隐藏文件显示策略放入设置，默认不显示。
- 支持新建文件、新建文件夹、重命名、拖动移动、删除和在系统文件管理器中显示。
- 新建文件默认扩展名为 `.md`；同目录重名、非法名称、保留名称和无权限写入时禁止提交并说明原因。
- 删除操作进入系统废纸篓/回收站；若平台能力不可用，必须二次确认永久删除，不能静默永久删除。
- 外部新增、删除、移动文件后，文件树增量更新并尽量保持展开状态。
- 当前文件被外部删除时，编辑内容保留为恢复副本，并提示另存或关闭。
- 文件树选择状态和编辑器内容保持一一对应；切换文件前确保当前文档已完成保存或进入明确的失败状态。

### 5.3 R3：所见即所得 Markdown 编辑

- 支持段落、H1～H6、粗体、斜体、删除线、行内代码、代码块、链接、图片、引用、有序/无序列表、任务列表、分隔线和表格。
- 输入 Markdown 标记后可以转为对应排版块；选中内容时提供克制的上下文工具栏或命令面板。
- 复制为纯文本、Markdown 和富文本时结果符合用户选择。
- 粘贴 HTML/富文本时转换为可表达的 Markdown；无法无损转换的结构必须提示或保留为受控 HTML，而不是静默丢弃。
- 保存前由统一序列化层生成 Markdown，避免编辑器组件直接拼接文件文本。
- 撤销与重做覆盖内容输入、结构变化和格式变化；文件系统重命名不混入正文撤销栈。
- 编辑器无法识别的语法保留原始文本，并可在源码模式中修改。

### 5.4 R4：文档大纲

- 根据当前文档 H1～H6 实时生成层级大纲。
- 点击大纲项定位到对应标题；编辑模式移动光标或滚动时，大纲高亮当前章节。
- 修改标题文字或层级后，大纲增量更新，不重置用户滚动位置。
- 同名标题通过稳定的文档位置标识区分；保存时不强制把内部标识写入 Markdown。
- 没有标题时展示“添加标题后将在这里生成大纲”，并提供插入一级标题的可执行入口。
- 大纲宽度由 R8 布局能力管理，可拖动、收起和恢复。

### 5.5 R5：自动保存、恢复和冲突

- 正常输入停止后执行防抖自动保存；切换文档、关闭窗口和应用退出前触发最终保存检查。
- 保存状态至少包含：未修改、已修改、保存中、已保存、保存失败、只读、外部冲突。
- 写入采用临时文件加原子替换或平台等价安全机制，防止中途写入导致原文件截断。
- 应用在本地应用数据目录保存短期恢复快照；恢复快照不能替代 `.md` 原文件。
- 每次写入前比较已知文件修改时间和内容摘要；发现外部变更时暂停自动覆盖。
- 冲突处理提供：重新加载磁盘版本、保留当前内容并覆盖、另存副本；覆盖行为必须二次确认。
- 保存失败时保持编辑内容和“未保存”状态，提供重试与另存，不显示成功提示。

### 5.6 R6：图片和资源

- 支持粘贴剪贴板图片、拖入本地图片和通过文件选择器插入图片。
- 默认资源目录为工作区内可配置的 `assets/`；路径配置由本机用户定义、应用保存、文件插入逻辑读取并消费。
- 图片名称冲突时自动生成可读且唯一的文件名，不覆盖既有图片。
- Markdown 中使用相对路径；移动 Markdown 文件导致相对关系变化时，应提示是否同步调整资源链接。
- 图片缺失时展示占位、原路径和重新定位入口，不移除原 Markdown 链接。
- 超大图片按容器宽度缩放显示，不修改原图；原图处理或压缩属于后续能力。

### 5.7 R7：Obsidian 式克制主题与阅读排版

- 内置 `Plainroot Neutral` 提供明亮、暗色和跟随系统模式；用户选择按工作区保存在应用偏好中并立即生效。
- 明亮主题基础令牌：界面灰 `#ECECED`、正文纸面 `#F3F3F2`、主文字 `#28282C`、次要文字 `#66666D`、分隔线 `#CECED2`、紫灰强调色 `#70677F`；暗色主题使用相同语义的低亮度映射，不直接反转颜色。
- 普通正文、标题、列表、引用和表格以中性色为主；紫灰强调色仅用于当前文件、链接、焦点、选区和当前大纲项，不按标题层级分配不同颜色。
- 成功、警告、危险等状态色只在相应状态、提示块或诊断信息出现，不能用于常驻装饰；状态同时使用图标、标题或边框，不能只依靠颜色区分。
- 删除多色渐变、文脉色轨、大面积彩色背景、装饰性光晕和正文悬浮卡片阴影。正文与中央画布形成连续平面，仅浮层、菜单和拖动反馈允许使用轻阴影。
- 页面识别点为右侧大纲当前项旁的单色细轨，只表达当前阅读位置，不延伸为正文多色装饰。
- 明亮主题正文纸面不得使用纯白，界面和正文亮度差保持克制；正文必须具备稳定的墨色重量，不能为了柔和而把正文、辅助文字和分隔层级整体做淡。
- 桌面正文默认使用 `17 px` 字号和 `1.76` 行高，窄容器可降至 `16.25 px`；正文保持约 `760～820 px` 最大行宽并随容器收窄，不能在宽屏无限拉长。
- 主题切换不得修改 Markdown 文件内容；任意文字颜色不在首版范围。
- UI、标题和正文优先使用系统无衬线字体栈，依靠字号、字重和留白建立层级；代码使用系统等宽字体栈，首版不强制打包额外字体。
- Obsidian 仅作为信息架构、密度、排版和配色参考；首版不复制其核心代码、品牌素材、图标资产或需要插件生态支撑的界面。

### 5.8 R8：自适应与区域拖动调宽

#### 5.8.1 布局对象

- 页面整体：应用窗口可由操作系统正常拖动缩放，应用根布局始终占满可用窗口，不出现浏览器式页面级滚动。
- 左侧区域：文件与文件夹目录。
- 中央区域：编辑/阅读画布，是主区域，获得剩余宽度。
- 右侧区域：当前文档大纲和单色当前章节指示轨。
- 顶部工具栏与底部状态栏固定高度，不提供无业务价值的自由调高；“各区域可拖动”特指三个主工作区的横向宽度调整。

#### 5.8.2 拖动规则

- 左侧目录与中央画布之间、中央画布与右侧大纲之间各提供一条可发现但克制的分隔条。
- 鼠标拖动分隔条时实时改变相邻区域宽度，不等待松开后才刷新。
- 分隔条支持键盘聚焦；方向键按固定步长调整，按住 Shift 使用大步长。
- 双击分隔条恢复对应区域默认宽度。
- 默认宽度建议：左侧 252 px，右侧 220 px；左侧允许 180～420 px，右侧允许 180～360 px。
- 中央区域桌面三栏状态下保留不小于 480 px 的可用宽度；达到限制后继续拖动不再压缩中央区域。
- 拖动过程中显示当前宽度反馈，但不得遮挡正文或造成持续闪烁。

#### 5.8.3 内容自适应规则

- 正文宽度使用容器宽度而不是仅使用窗口宽度计算；任一侧栏变化都触发正文重新排版。
- 正文内边距、字号和行宽使用有上下限的流式策略；避免宽屏一行过长，也避免窄屏内边距挤占内容。
- 普通文本和列表自动换行；图片、视频和嵌入内容最大宽度不超过正文容器。
- 表格超出正文时只允许表格自身横向滚动；代码块超宽时只允许代码块自身横向滚动，不产生应用页面级横向滚动。
- 长链接和连续字符可安全断行，但代码与文件路径优先在自身容器滚动。
- 编辑器选区、光标位置、撤销栈和当前大纲项不因宽度变化重置。
- 阅读模式宽度变化后重新计算分页，并以当前标题/段落锚点恢复位置，不能仅依赖旧页码。

#### 5.8.4 窄窗口退化

- 正常宽度优先展示三栏。
- 空间不足时先将右侧大纲收为可唤出的抽屉，再将左侧文件树收为可唤出的抽屉，中央画布始终保留。
- 自动收起只改变当前呈现，不覆盖用户保存的理想宽度；窗口恢复后还原此前宽度。
- 用户手动收起左右区域后，中央区域使用释放的全部宽度。
- 无论自动或手动收起，工具栏均保留重新打开目录和大纲的明确入口。

#### 5.8.5 偏好保存与回退

- 谁定义：本机用户通过拖动、收起、展开或“重置布局”定义。
- 谁保存：桌面应用保存到应用数据目录的工作区偏好中，不写入 Markdown 文件。
- 谁读取：工作区打开时由布局状态层读取。
- 谁消费：工作台三栏布局、正文容器和分页计算模块。
- 默认值：左侧 252 px、右侧 220 px，中央区域占剩余宽度。
- 非法值处理：版本升级、显示器变化或偏好损坏导致超限时按当前最小/最大值夹取；无法解析时回退默认值。
- 失效与回退：设置中的“重置布局”清除当前工作区布局偏好并恢复默认值。

### 5.9 R9：编辑、专注和分页阅读模式

- 编辑模式：中央画布是唯一正文纵向滚动归属，外层应用不滚动；可隐藏滚动条视觉，但必须保留鼠标、触控板和键盘滚动能力。
- 专注模式：隐藏左右辅助区域和非核心工具，保留保存状态、退出专注入口和正文。
- 阅读模式：正文不可编辑，按页面显示，不出现正文纵向滚动条。
- 阅读模式支持方向键、PageUp/PageDown、空格键、滚轮和页面按钮翻页，并显示当前页/总页数。
- 模式切换保留当前标题或段落锚点；从阅读切回编辑时定位到相同内容。
- 单个代码块、表格或图片高于一页时允许该块内部滚动或采用专门展开查看，不能裁掉内容。
- 系统开启“减少动态效果”时，翻页和侧栏变化取消非必要动画。

### 5.10 R10：Markdown 源码模式

- 用户可在所见即所得与源码模式间切换。
- 切换前统一提交当前编辑器状态，切换后使用同一 Markdown 内容源，不维护两个互相竞争的文档副本。
- 源码模式提供语法高亮、行号、查找替换和基础括号匹配。
- 从源码返回所见即所得时，语法错误或不支持节点必须定位并提示；原始源码仍可保存，不能强制删除。

### 5.11 R11：反馈、键盘与无障碍

- 顶部或状态栏持续显示文档名、保存状态、当前模式、字数和当前位置。
- 所有图标按钮拥有可读名称和悬停说明；键盘焦点清晰可见。
- 文件目录、大纲和弹出菜单支持键盘导航。
- 分隔条使用可访问的 separator 语义并暴露当前宽度、最小值和最大值。
- 错误提示说明发生了什么、内容是否安全以及用户下一步可执行操作。
- 快捷键至少覆盖：打开、保存、新建、搜索、切换编辑/源码/阅读、显示目录、显示大纲和退出专注。
- Windows 与 macOS 按平台使用 Ctrl/Command 惯例，界面文案显示当前平台组合键。

### 5.12 R12：全文搜索

- 搜索范围为当前工作区内受支持的 Markdown 文件。
- 结果包含文件名、相对路径、命中片段和匹配高亮；点击结果打开文件并定位内容。
- 文件变化后增量更新索引；索引不可用时允许降级扫描并提示性能差异。
- Markdown 文件仍是事实源；索引可删除并完整重建。
- 中文搜索首版需通过真实中文语料验证分词或子串匹配效果，不能只使用英文测试数据宣称完成。

### 5.13 R13：多文档页签与最近关闭文档

- 每个工作区窗口拥有自己的文档页签集合；点击文件树、搜索结果或最近文档时打开真实页签，不通过替换唯一文档模拟切换。
- 同一路径在同一窗口只允许一个页签；再次打开时聚焦已有页签并恢复该页签的光标与滚动位置。
- 页签至少显示文件名、关闭入口和非颜色保存状态；同名文件通过父级路径提示或悬停说明区分。
- 单页签状态至少包含加载中、干净、已修改、保存中、保存失败、只读和外部冲突；活动页签驱动中央编辑器、大纲、状态栏和窗口标题。
- 支持鼠标拖动排序、键盘切换、关闭当前、关闭其他、关闭右侧、关闭全部和重新打开最近关闭文档；页签过多时使用横向滚动及溢出菜单，不无限压缩文字。
- 关闭已修改、保存失败或冲突页签时执行保存检查；用户可重试保存、另存、放弃修改或保持页签打开，未明确选择前不得丢弃内容。
- 各页签独立保存排版编辑/源码/阅读模式、光标、选区、滚动或阅读锚点及撤销栈；共享当前窗口的工作区目录、三栏布局和主题选择。
- 应用退出或窗口关闭后，将打开页签、活动页签和最近关闭列表保存到工作区会话；恢复失败不影响磁盘文件。
- 首版不实现预览页签、固定页签和跨窗口拖拽页签，避免在基础生命周期稳定前引入隐式替换和跨工作区移动语义。

### 5.14 R14：一目录一窗口与多窗口生命周期

- 一个窗口只绑定一个根工作区目录；首版不在同一窗口附加多个根目录。
- 当前窗口已有工作区时打开其他目录，必须展示“当前窗口打开”“新窗口打开”“取消”三个明确结果。
- 选择当前窗口时，先完成全部页签的保存检查，再关闭原工作区会话并在同一窗口载入新目录；任一保存阻塞未处理时不得替换。
- 选择新窗口时创建独立原生窗口，原窗口及其页签保持不变；新窗口拥有独立文件树、搜索索引视图、页签、布局、窗口尺寸和活动文档。
- 对话框可保存“每次询问 / 当前窗口 / 新窗口”的默认偏好，设置页必须能够恢复为每次询问。
- 同一目录已在其他窗口打开时，默认聚焦已有窗口，不创建可能并发写入同一工作区的重复窗口。
- 启动页展示最近工作区；关闭单个窗口只关闭该工作区会话，退出应用才处理全部窗口。macOS 无窗口时是否保留应用进程遵循平台惯例。
- 正常退出和异常恢复保存各窗口的目录、位置、尺寸、布局、页签和活动页签；恢复时逐个校验目录权限，失效目录进入重新授权或移除流程。
- `Cmd/Ctrl+W` 关闭当前页签，`Cmd/Ctrl+Shift+W` 关闭窗口，`Cmd/Ctrl+Shift+N` 新建窗口；实际界面显示当前平台快捷键。

### 5.15 R15：可编辑颜色主题预设与实时预览

- 主题工作室从“设置 > 外观 > 颜色预设”进入，展示内置预设、自定义预设和当前应用状态。
- `Plainroot Neutral` 是只读、不可删除的默认回退预设；用户需复制内置预设或新建自定义预设后编辑。
- 支持新建、复制、重命名、编辑和删除自定义预设；名称去除首尾空白后在预设库中唯一。
- 每套预设包含明亮与暗色两套语义颜色；跟随系统只决定使用哪一套，不创建第三套颜色。
- 首版开放的稳定令牌包括：应用界面、正文纸面、标题文字、正文文字、辅助文字、分隔线、强调色，以及成功、警告、危险状态色；悬停、选区、代码底色和禁用态等衍生色由系统计算。
- 编辑令牌时同时更新当前窗口和工作室示例文档，形成实时预览；其他窗口在保存前不受草稿影响。
- 保存后更新全局预设库，并同步到正在使用该预设的窗口；取消、Esc 或关闭含未保存草稿的工作室时回退到进入前预设和值。
- 普通正文与纸面的常规文字对比不得低于 `4.5:1`，大标题不得低于 `3:1`；不足时显示具体令牌和对比值，阻止保存但允许继续调整预览。
- 删除当前使用中的自定义预设前先选择回退预设；删除失败或预设数据损坏时保持现有窗口颜色并回退 `Plainroot Neutral`。
- 预设定义保存在操作系统应用数据目录并跨窗口共享；工作区只保存当前预设标识及明亮/暗色/跟随系统选择。
- 颜色预设只影响应用和阅读渲染，不向 Markdown 写入颜色、HTML 或私有元数据；字体、字号、行高和正文宽度仍由独立排版设置管理。
- 首版不实现预设在线市场、远程同步和导入第三方 Obsidian 主题源码。

## 6. 数据与接口需求

### 6.1 内容与辅助数据边界

| 数据 | 保存位置 | 事实源 | 说明 |
| --- | --- | --- | --- |
| Markdown 正文 | 用户工作区 `.md` 文件 | 是 | 可由其他编辑器直接读写 |
| 图片与附件 | 工作区资源目录 | 是 | Markdown 使用相对路径引用 |
| 最近工作区 | 操作系统应用数据目录 | 否 | 路径失效后允许清理 |
| 窗口与页签会话 | 应用数据目录，按工作区和窗口区分 | 否 | 保存窗口位置、页签顺序、活动页签与内容锚点 |
| 布局宽度和收起状态 | 应用数据目录，按工作区区分 | 否 | 不污染 Markdown 文件 |
| 颜色主题预设库 | 应用数据目录，全局共享 | 否 | 内置预设只读；非法值回退 `Plainroot Neutral` |
| 工作区主题选择 | 应用数据目录，按工作区区分 | 否 | 仅保存预设标识和明暗模式 |
| 字体与阅读排版偏好 | 应用数据目录 | 否 | 与颜色预设分离 |
| 搜索索引 | 应用数据目录 | 否 | 可从工作区重建 |
| 恢复快照 | 应用数据目录 | 否 | 有期限清理，不替代原文件 |

### 6.2 文件服务能力

开发计划至少要覆盖以下内部能力边界：

- 选择并授权文件/目录。
- 读取目录、读取文件、写入文件、重命名、移动、删除到回收站。
- 监听目录和文件变化，并对应用自身写入去重。
- 计算文件修改时间和内容摘要，用于冲突判断。
- 写入临时文件并安全替换。
- 保存与读取工作区偏好、最近记录、恢复快照和搜索索引。
- 创建、聚焦、关闭和恢复原生窗口，并按工作区保存窗口与页签会话。
- 保存、校验、读取和删除自定义颜色预设，保证预览草稿与已保存预设隔离。

### 6.3 一致性要求

- 文件树、当前文档路径、标题栏和保存目标必须一致。
- 文件移动或重命名完成后再更新应用状态；失败时保持旧路径和旧选择。
- 布局拖动只修改偏好，不触碰 Markdown 文件内容或正文撤销栈。
- 索引更新失败不得阻塞正文保存；搜索可以降级，正文不可丢失。
- 外部文件变化与应用保存并发时，以冲突状态中止自动覆盖。
- 页签路径、文件树选择、中央编辑器、大纲、状态栏和窗口标题始终指向同一活动文档。
- 当前窗口替换工作区前必须解决全部阻塞保存状态；未完成时不得清空页签集合。
- 主题预览草稿仅作用于发起预览的窗口；保存后才更新全局预设库和其他消费窗口。

## 7. 页面与交互开发需求

### 7.1 页面 P1：Markdown 编辑工作台

- 对应需求编号：R1～R15。
- 页面类型：新增复杂桌面工作台。
- 页面入口：打开工作区、打开 Markdown 文件或选择最近工作区后进入。
- 原型文件：`prototypes/markdown-workbench.html`。
- 页面布局：
  - 布局事实源：对齐 `prototypes/markdown-workbench.html`。
  - 原生窗口层：平台窗口控制、可拖动标题区、工作区名称和“文件/编辑/显示/窗口/帮助”菜单；macOS 与 Windows 按平台惯例适配。
  - 页签层：展示真实文档页签、活动态、保存状态、关闭入口、溢出列表和新建文档入口。
  - 文档工具层：保留侧栏开关、搜索、排版编辑/Markdown 源码/阅读切换、专注和保存状态；主题预设与布局重置进入设置或更多菜单。
  - 左侧栏：文件目录、文件/文件夹新建入口、选中状态和空状态。
  - 左分隔条：拖动调整左侧宽度，双击复位，支持键盘方向键。
  - 中央主区：自适应连续文档画布；不使用悬浮纸张卡片、彩色渐变或装饰性光晕，编辑模式内部受控滚动，阅读模式分页。
  - 右分隔条：拖动调整右侧宽度，双击复位，支持键盘方向键。
  - 右侧栏：当前文档大纲、章节高亮和单色当前章节细轨。
  - 底部状态栏：字数、当前模式、文件类型、光标/章节、分页信息。
  - 弹窗/抽屉/设置入口：窄窗口下左右栏转为抽屉；打开其他目录、冲突处理、重置布局、资源目录和颜色预设通过对话框或设置承载。
  - 滚动归属：应用根页面不滚动；编辑模式仅中央画布纵向滚动；表格和代码块可局部横向滚动；阅读模式正文翻页。
  - 关键状态与退化：加载、空工作区、无标题、页签溢出、只读、保存失败、外部冲突、工作区替换确认、窄窗口、侧栏收起和索引降级均有明确反馈。
- 数据来源：本地工作区文件、文档解析结果、应用偏好和本地搜索索引。
- 权限与可见性：本机用户仅能访问已授权路径；只读状态隐藏或禁用写操作并说明原因。
- 组件复用与通用能力：
  - 已有通用能力：未发现现有项目组件、布局模板或设计系统。
  - 可能新增能力：可复用的原生窗口适配层、文档页签栏、三栏可调整布局、可访问分隔条、工作区文件树、文档大纲、保存状态、主题令牌和分页阅读器。
  - 配置化承载：布局宽度、收起状态、主题、资源目录和阅读偏好按 5.8.5 与 6.1 保存、读取、消费和回退。

#### 7.1.1 页面功能点：打开工作区与文件导航

- 对应需求编号：R1、R2。
- 默认展示：最近工作区或空状态“打开一个 Markdown 文件夹”。
- 用户操作：打开目录、展开目录、选择文件、新建、重命名、移动、删除。
- 输入与校验：系统授权路径、合法文件名、同目录唯一性和写权限。
- 状态变化：工作区加载、文件选择、文件树增量刷新、最近记录更新。
- 保存/提交/取消：涉及删除和重命名时必须有可取消流程；失败不更新路径状态。
- 加载状态：大目录扫描显示进度，允许先展示已扫描部分。
- 空状态：提供打开文件夹和新建文档入口。
- 错误状态：展示路径、失败原因和重试/重新授权入口。
- 权限不足状态：文件树可见但写操作禁用；完全不可读时停止扫描。
- 数据刷新：文件监听增量更新，必要时允许手动刷新。
- 与其他功能点的联动：选择文件更新编辑器、大纲、搜索定位和状态栏。
- 验收标准：覆盖 R1、R2 对应验收项。

#### 7.1.2 页面功能点：编辑、源码与保存

- 对应需求编号：R3、R5、R6、R10、R11。
- 默认展示：所见即所得编辑模式和当前保存状态。
- 用户操作：输入、格式化、粘贴图片、撤销重做、切换源码、保存、另存。
- 输入与校验：Markdown 语法、图片资源路径、文件写权限、外部修改摘要。
- 状态变化：未修改→已修改→保存中→已保存，或进入保存失败/只读/冲突。
- 保存/提交/取消：自动保存与手动保存共享写入链路；冲突覆盖需二次确认。
- 加载状态：文档解析时显示骨架，不允许编辑未完成加载的旧内容。
- 空状态：空文档显示可直接输入的标题占位，不写入无意义占位文本。
- 错误状态：解析失败可进入源码模式；保存失败保留当前内容。
- 权限不足状态：切换只读并提供另存副本。
- 数据刷新：内容变化增量更新大纲、字数和搜索索引任务。
- 与其他功能点的联动：模式切换保留内容锚点和撤销边界。
- 验收标准：覆盖 R3、R5、R6、R10、R11 对应验收项。

#### 7.1.3 页面功能点：自适应布局和区域调宽

- 对应需求编号：R8、R11。
- 默认展示：三栏布局，左侧 252 px、右侧 220 px、中央占剩余宽度。
- 用户操作：拖动/键盘调节左右分隔条、双击复位、收起或展开侧栏、重置布局、缩放应用窗口。
- 输入与校验：宽度被限制在各区域允许范围，并保障中央最小宽度。
- 状态变化：拖动期间实时更新 CSS 布局与宽度反馈；结束后持久化工作区偏好。
- 保存/提交/取消：拖动松开即保存；重置布局立即保存默认值；偏好写入失败不影响正文。
- 加载状态：偏好读取前使用默认值，读取完成后避免明显布局闪跳。
- 空状态：不适用；没有文档时仍可调整目录区域。
- 错误状态：非法偏好被夹取或回退，并允许重置。
- 权限不足状态：应用数据目录不可写时本次会话仍可调整，但提示无法记住布局。
- 数据刷新：窗口、区域宽度和显示器缩放变化触发内容重排和阅读分页重算。
- 与其他功能点的联动：正文光标、大纲当前项、阅读锚点和保存状态保持不变。
- 验收标准：覆盖 R8、R11 对应验收项。

#### 7.1.4 页面功能点：大纲、专注与分页阅读

- 对应需求编号：R4、R7、R9。
- 默认展示：右侧大纲和编辑模式；大纲高亮当前章节。
- 用户操作：点击标题定位、进入专注、进入阅读、翻页、退出阅读。
- 输入与校验：分页基于当前容器尺寸和渲染结果；无标题时使用段落锚点。
- 状态变化：编辑/专注/阅读模式切换，大纲当前项和单色章节细轨同步更新。
- 保存/提交/取消：进入阅读前先提交当前编辑状态；保存失败时允许阅读但持续显示未保存状态。
- 加载状态：分页重算显示短暂进度或禁用翻页，完成后恢复锚点。
- 空状态：无标题提示添加标题；空文档阅读模式显示空文档说明。
- 错误状态：分页失败时降级为只读连续视图，并明确说明。
- 权限不足状态：只读文件仍可使用大纲、专注和阅读。
- 数据刷新：正文变化、窗口变化、字体或侧栏宽度变化触发大纲或分页刷新。
- 与其他功能点的联动：从阅读返回编辑时定位同一标题/段落。
- 验收标准：覆盖 R4、R7、R9 对应验收项。

#### 7.1.5 页面功能点：全文搜索

- 对应需求编号：R12。
- 默认展示：搜索入口关闭，不占用正文空间。
- 用户操作：输入关键词、上下选择结果、点击定位、清除搜索。
- 输入与校验：空关键词不执行搜索；特殊字符按搜索语法转义或作为普通文本处理。
- 状态变化：搜索中、结果、无结果、索引降级或索引重建。
- 保存/提交/取消：不修改 Markdown 内容。
- 加载状态：大工作区显示搜索和索引进度。
- 空状态：说明当前工作区没有匹配内容。
- 错误状态：索引错误时允许重建或降级扫描。
- 权限不足状态：跳过无法读取文件并列出数量，不暴露内容。
- 数据刷新：文件保存和外部变化后更新索引。
- 与其他功能点的联动：点击结果打开文档、定位片段并同步大纲。

#### 7.1.6 页面功能点：多文档页签

- 对应需求编号：R5、R13。

- 用户操作：打开、切换、拖动排序、关闭、关闭其他、关闭右侧、关闭全部、通过溢出菜单定位和重新打开最近关闭文档。
- 输入与校验：文档绝对路径在当前窗口唯一；同名页签显示父级路径说明。
- 状态变化：加载中、干净、已修改、保存中、保存失败、只读、冲突和关闭中。
- 保存/提交/取消：阻塞状态关闭时提供重试、另存、放弃或保持打开；取消关闭不改变页签和编辑器。
- 加载状态：新页签先展示稳定占位，不闪现前一文档内容。
- 空状态：解释可从目录或 `Cmd/Ctrl+O` 打开文档。
- 错误状态：读取失败页签保留路径和重试/源码打开入口，不假装空文档。
- 权限不足状态：只读页签保留查看、复制、大纲和阅读能力。
- 数据刷新：活动页签改变时同步窗口标题、文件树选择、编辑器、大纲和状态栏。

## 8. 边界条件与异常场景

| 场景 | 处理要求 |
| --- | --- |
| 超大 Markdown 文件 | 分阶段解析或虚拟化，显示加载进度；不能无响应后丢失输入 |
| 数千文件工作区 | 增量扫描和索引，不阻塞打开首个文件 |
| 文件编码不是 UTF-8 | 检测并提示；未经确认不以 UTF-8 覆盖原文件 |
| 文件换行符为 CRLF/LF | 保存时优先保留原文件换行风格 |
| 同名标题 | 内部定位稳定，不强制向 Markdown 注入私有 ID |
| 表格/代码块超宽 | 仅内容块自身横向滚动，不扩大页面 |
| 图片或单块内容高于阅读页 | 块内滚动、缩放或展开查看，不裁切丢失 |
| 拖动分隔条越界 | 夹取到最小/最大值，保持中央最小宽度 |
| 拖动时窗口同时变化 | 按最新容器尺寸重新夹取，不能产生负宽度或布局跳出窗口 |
| 高 DPI/显示器切换 | 按 CSS 像素和当前缩放重算，非法历史宽度自动回退 |
| 外部修改当前文件 | 暂停自动覆盖，进入冲突处理 |
| 外部删除当前文件 | 保留恢复副本，允许另存或关闭 |
| 应用异常退出 | 下次启动提供恢复快照，并展示快照时间和原文件状态 |
| 搜索索引损坏 | 删除并重建索引，不影响原文件和编辑保存 |
| 应用偏好损坏 | 使用默认布局和主题，并允许重置 |
| 关闭存在未保存或保存失败的页签 | 阻止静默关闭，提供重试、另存、放弃或保持打开 |
| 页签数量超过可用宽度 | 保持最小可读宽度，使用横向滚动和溢出菜单定位 |
| 当前窗口替换目录时有阻塞页签 | 中止替换并保留原工作区，直至逐项解决或取消 |
| 同一目录已在其他窗口打开 | 聚焦已有窗口，不创建重复写入会话 |
| 恢复时目录失效或权限撤销 | 单独标记失效窗口，允许重新授权或移除，不阻塞其他窗口恢复 |
| 主题预览中直接关闭设置 | 提示保存、放弃或取消关闭；放弃后原子回退进入前颜色 |
| 自定义预设对比度不足 | 显示具体颜色对及比值，允许继续预览但禁止保存 |
| 删除当前使用中的预设 | 先选择回退预设；失败时维持原预设或回退 `Plainroot Neutral` |

## 9. 性能、安全与兼容性要求

### 9.1 性能

- 分隔条拖动和窗口缩放以可感知连续的帧率更新；不得在每个指针移动事件中同步写磁盘或重建全文索引。
- 拖动期间只更新内存布局；松开或短时防抖后持久化宽度。
- 正文重排不重建编辑器实例；分页重算与正文编辑状态解耦。
- 工作区扫描、索引和大文件解析在后台执行，避免阻塞主界面输入。
- 页签切换复用文档会话并延迟加载非活动重资源；不能每次切换都重新解析全部工作区。
- 多窗口各自渲染界面，但文件监听、索引和预设广播应复用受控后台能力，避免窗口数线性复制重任务。
- 颜色令牌预览以 CSS 变量或等价机制增量更新，不重建编辑器和全文布局；输入高频时不同步写磁盘。
- 文件监听事件合并并区分应用自身写入，防止保存循环。
- 恢复快照和索引必须有容量与清理策略，禁止无限增长。

### 9.2 安全

- 文件系统访问限制在用户选择和授权范围内，防止路径穿越。
- 渲染 Markdown 内嵌 HTML 时执行白名单清理；默认禁止脚本、事件属性和不安全协议。
- 外部链接在系统浏览器打开前显示目标；危险协议不执行。
- 远程图片和内容默认不获得文件系统或应用命令能力。
- 删除、覆盖冲突和不可逆操作必须提供明确确认。
- 同一目录默认只允许一个工作区窗口，降低多个窗口并发覆盖相同文件的风险。
- 搜索索引和恢复快照可能含正文内容，应保存在本机应用数据目录并可由用户清理。

### 9.3 兼容性与可访问性

- 支持当前产品确认的 Windows 与 macOS；发布前分别验证文件路径、回收站、快捷键、窗口控制、系统菜单、多窗口恢复、窗口缩放和 WebView 排版。
- 支持系统明暗主题和减少动态效果设置。
- 核心功能可以仅使用键盘完成；焦点顺序与视觉顺序一致。
- 颜色对比满足常规正文阅读要求，状态不能只用颜色表达。
- 分隔条可被鼠标、触控板和键盘操作。
- Markdown 文件在其他通用编辑器中仍可读取；产品语义色不写入普通正文。

## 12. 建议开发顺序

| 阶段 | 目标 | 覆盖需求 | 前置与关联 | 可验证里程碑 |
| --- | --- | --- | --- | --- |
| 1 | 建立原生桌面壳、本地权限、文件模型、安全写入和多窗口管理 | R1、R2、R5、R14 | 所有内容能力的底座 | 能打开真实目录、选择当前/新窗口并安全保存与恢复 |
| 2 | 建立统一 Markdown 文档模型和两种编辑模式 | R3、R6、R10 | 依赖阶段 1 文件读写 | 常用语法与图片完成 Markdown 往返测试 |
| 3 | 建立多文档页签状态机 | R5、R13 | 依赖统一文档模型与安全保存 | 页签切换、关闭保护、最近关闭和会话恢复通过 |
| 4 | 建立三栏工作台、设计令牌和自适应布局基础 | R7、R8、R11 | 可与阶段 2～3 并行原型，集成时依赖编辑器容器 | 拖动、键盘调宽、持久化和窄窗口矩阵通过 |
| 5 | 接入主题工作室、全局预设库和窗口级预览 | R7、R15 | 依赖设计令牌和多窗口广播边界 | CRUD、对比度、取消回退和跨窗口保存同步通过 |
| 6 | 接入大纲、专注和分页阅读 | R4、R9 | 依赖统一文档模型与自适应容器 | 模式切换和宽度变化保持内容锚点 |

后续开发计划建议单独细化五个高复杂度模块：Markdown 无损往返模型、分页阅读排版算法、文件保存/外部冲突状态机、页签与窗口生命周期、主题草稿与跨窗口同步。它们分别影响内容兼容性、阅读稳定性、数据安全和桌面会话一致性，不应只作为普通页面任务处理。
