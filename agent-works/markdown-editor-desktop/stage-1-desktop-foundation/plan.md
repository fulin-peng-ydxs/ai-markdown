## 1. 需求来源与目标

- 需求文档：`agent-works/markdown-editor-desktop/requirement.md`。
- 上游闭环：`agent-works/markdown-editor-desktop/requirement-closure.md`。
- 页面原型：
  - `agent-works/markdown-editor-desktop/prototypes/markdown-workbench.html`；
  - `agent-works/markdown-editor-desktop/prototypes/workspace-launcher.html`；
  - `agent-works/markdown-editor-desktop/prototypes/theme-preset-studio.html`。
- 功能目标：在真实 macOS/Windows 桌面壳内打开用户授权的目录或 Markdown 文件，建立受根目录约束的文件模型，完成文件树、文件与文件夹管理、安全写入原语、最近工作区、原生窗口创建、同目录窗口聚焦和目录打开决策壳，为后续文档模型、页签和保存状态机提供可测试底座。
- 第一阶段边界：
  - 完成 R1 的桌面壳、本地授权和离线底座子集；
  - 完成 R2 的扫描、读取、文件树、增删改移、回收站、外部变化监听等文件系统子集；
  - 完成 R5 的安全写入、文件修订信息和失败不破坏原文件子集，不宣称完成自动保存、恢复快照或外部冲突状态机；
  - 完成 R14 的窗口创建、同目录聚焦、目录决策、最近记录和根工作区会话子集，不宣称完成多页签保存检查与完整会话恢复；
  - P2 启动页和 P1 工作台壳进入第一阶段；P1 编辑、页签、完整布局、阅读、搜索及 P3 主题工作室由后续独立阶段计划承接。
- 本次不做：R3～R4、R6～R13、R15、R30、R32 的完整产品能力；R11、R31 仅承接 P1/P2 壳所需子集；R16、R17、R24～R26、R33、R34 后续建议；R18～R23、R27～R29 暂不实现项。阶段外需求仅保留范围状态、验收依据和另立计划约束，不在第一阶段预占后续任务编号。
- 计划规则例外：`auto-plan-dev` 原则上要求每个必须实现项至少对应一个任务；本文件是用户明确要求的第一阶段专属计划，且用户明确要求不放置后续阶段占位任务，因此阶段外必须实现项有意识地采用“跳过 + 未覆盖 + 另立计划义务”登记，任务编号延至对应阶段计划分配。这是阶段化取舍，不代表取消产品义务；进入对应阶段前必须消除该项未覆盖状态。
- 计划输出目录：`agent-works/markdown-editor-desktop/stage-1-desktop-foundation/`。

## 2. 当前项目依据

### 2.1 仓库与工具链事实

- 当前仓库已完成 T1～T15：除桌面壳、授权、文件 CRUD、删除/定位、外部监听、安全写入和窗口协调外，P2 启动页与 P1 第一阶段工作台壳已真实消费系统选择器、授权确认、窗口决策、渐进文件树、只读 Markdown 和磁盘操作；P1/P2 共享对话框与类型化异步状态契约已收口，并已建立隔离的 macOS 桌面 E2E。尚无自动保存、恢复快照、完整外部冲突状态机、编辑器/页签/大纲、数据库、Windows 验证或 CI 基线。
- 本机 NVM 已安装 Node `v24.11.1`、npm `11.6.2`、Corepack `0.34.2` 和 pnpm `11.5.1`；当前默认 Node 仍为 18，因此项目必须用 `.nvmrc` 和 `packageManager` 固定工具链，所有本地命令先执行 `nvm use`。
- 本机已安装 macOS Command Line Tools、Apple Clang 16，以及由 T1 安装并锁定的 Rust/Cargo 1.97.1、rustfmt 与 clippy；完整 Xcode 未安装且移动端不在本阶段范围。
- Windows 实机无法由用户提供。第一阶段使用 GitHub Actions `windows-latest` 完成真实 Windows 编译、Rust/前端测试和 WebdriverIO 桌面 E2E；原生文件选择器、系统回收站、文件管理器定位等不适合稳定无人值守验证的交互，保留为最终跨平台/发布前 Windows 人工验收，不虚假标记为已通过。
- 技术依据：Tauri 2 官方要求 Rust 和 LTS Node，Vite 8 支持 Node 20.19+ 或 22.12+；Tauri 官方测试方案支持 mock runtime、WebdriverIO Tauri 服务和 CI runner。依赖锁定时记录精确版本、许可证和安全审计结果。

### 2.2 页面与设计依据

- 前端视觉、布局和交互的权威规范是仓库根目录 `DESIGN.md`；P1/P2 的实现任务 T12～T14 必须逐项执行 `agent-works/markdown-editor-desktop/page-development-workflow.md`，原型只提供区域、状态和交互证据，不能覆盖正式规范。
- P1 布局事实源是 `prototypes/markdown-workbench.html`：原生窗口层、页签层、文档工具层、左文件树、中部画布、右大纲、状态栏和目录决策对话框。
- P2 布局事实源是 `prototypes/workspace-launcher.html`：打开文件夹/文件、最近工作区、过滤、过滤空态、失效记录、重新授权、会话恢复和加载状态。
- P3 布局事实源是 `prototypes/theme-preset-studio.html`；第一阶段不开发、不生成替代页面，也不预建无消费的主题组件。
- 第一阶段只消费 `DESIGN.md` alpha 语义 token，不在页面复制私有 hex、间距、圆角或状态色；状态不能只靠颜色表达。T8 已建立首个运行时语义 token 文件并由永久删除对话框消费，其余页面仍须复用同一 token 源；代码与自动化测试成为已落地区域的数值事实源。
- P1/P2 至少覆盖 `ready/loading/empty/error`，文件场景按需覆盖 `readonly/dirty/saving/conflict/missing/permission-denied`；阶段 1 不存在的编辑状态必须隐藏而非伪造。状态优先级为：安全阻塞状态（权限撤销/根失效）高于操作失败，高于 loading/processing，高于 empty/ready。
- 关键窗口验证遵循 `DESIGN.md`：完整桌面、约 `1050px`、约 `820px`，P2 另测约 `760px` 单列临界宽度；标题栏和主内容不得形成额外整页滚动。
- 对话框使用具体动作动词，支持 Esc、焦点圈定和关闭后焦点恢复；Toast 只用于已完成的轻量结果，不承载选择、失败恢复或长期状态。

### 2.3 推荐技术基线确认结果

- 桌面壳：Tauri 2。
- 前端：React + TypeScript + Vite 8，使用 pnpm，精确依赖由 `pnpm-lock.yaml` 锁定。
- 后端：Rust stable；工作区读写通过 Rust 命令层集中实现，前端不持有 `$HOME/**/*` 等宽泛文件系统权限。
- 系统桥接：按任务实际需要评估 Tauri dialog、single-instance、window-state、opener 等官方插件；删除到回收站使用通过许可证审查的跨平台 Rust 实现；T9 使用锁定版本 `notify` 8.2.0 的平台原生 watcher 并在 Rust 内完成有界合并。T4 因原子替换要求采用 Rust 私有 JSON 仓储，没有注册 Tauri Store 插件或前端 Store 权限。
- 第一阶段辅助状态：版本化 Rust JSON 状态仓储；全文搜索阶段再评估 SQLite/FTS5，不在阶段 1 引入数据库。
- Markdown 内容事实源：用户工作区中的真实 `.md` 文件。

## 4. 技术方案

### 4.1 工程结构与模块边界

计划采用以下目标结构；实际脚手架生成后如工具默认目录略有差异，只允许调整路径，不改变职责边界：

```text
.
├── .github/workflows/ci.yml
├── .nvmrc
├── package.json
├── pnpm-lock.yaml
├── rust-toolchain.toml
├── src/
│   ├── app/
│   ├── components/
│   ├── features/launcher/
│   ├── features/workbench/
│   ├── services/desktop/
│   └── test/
├── src-tauri/
│   ├── capabilities/
│   ├── src/
│   │   ├── commands/
│   │   ├── fs/
│   │   ├── menu.rs
│   │   ├── state.rs
│   │   ├── window.rs
│   │   └── lib.rs
│   ├── Cargo.toml
│   ├── Cargo.lock
│   └── tauri.conf.json
└── tests/fixtures/workspaces/
```

- React 只负责视图、用户意图和可观察状态，不直接拼接任意绝对路径执行写操作。
- Rust 命令层负责根目录授权登记、规范化路径、路径越界检查、文件扫描、CRUD、安全写入、回收站和窗口协调。
- `WorkspaceRegistry` 保存当前进程内 `canonicalRoot → windowLabel` 映射；Windows 路径进行大小写和前缀规范化，避免同一目录因文本差异被重复打开。
- 用户已确认选择单个 `.md` 文件时以其父目录作为工作区根目录，并把该文件作为初始活动目标；打开前必须显示将被授权和扫描的父目录路径，允许取消。若父目录已打开则只聚焦现有窗口。
- 同时保留用户选择的原始路径与解析后的 `canonicalRoot`。所选根本身是符号链接时，必须在授权提示中展示解析后的目标并经用户继续确认，去重与根内判定均使用该目标；根内符号链接节点默认不跟随，防止越过授权根或形成循环。
- 隐藏文件默认不展示；`showHidden=false` 是第一阶段命令默认值而非可持久化用户配置。设置入口和配置读写由后续独立阶段闭环实现。

### 4.2 第一阶段核心数据契约

| 模型 | 关键字段 | 生产者 | 消费者 | 校验与失败 |
| --- | --- | --- | --- | --- |
| `WorkspaceDescriptor` | `id`、`selectedPath`、`canonicalRoot`、`displayName`、`writable`、`initialFile` | Rust 授权服务 | P1、窗口协调器、状态仓储 | 根路径存在、可读且规范化；根为链接时展示解析目标并确认；失败返回稳定错误码 |
| `FsEntry` | `relativePath`、`name`、`kind`、`writable`、`symlink`、`childrenState` | 扫描服务 | 文件树 | 禁止返回根外绝对路径；不可读项带错误状态 |
| `FileRevision` | `modifiedAt`、`size`、`contentHash`、`encoding`、`lineEnding` | 读取/安全写服务 | 后续 R5 状态机 | 非 UTF-8 不覆盖；混合换行显式标记 |
| `RecentWorkspace` | `workspaceId`、`canonicalRoot`、`displayName`、`lastOpenedAt`、`availability` | 工作区服务 | P2 | 打开前重新检查，不信任历史可用状态 |

### 4.3 安全写入与文件一致性

- 同目录创建临时文件，写入后 `flush`/必要时 `sync_all`，再执行平台适配的安全替换；新文件与覆盖文件分别处理。
- POSIX 使用同文件系统原子重命名；Windows 使用经过 PoC 验证的替换 API，目标被占用或替换失败时保留原文件并返回错误。
- 写入前后返回 `FileRevision`，供后续编辑冲突与全文搜索阶段通过稳定契约复用。
- 第一阶段只暴露“显式测试写入/文件操作”所需原语，不实现防抖自动保存，不把底层写入成功冒充 R5 整体验收通过。
- 新建、重命名、移动和删除均以磁盘成功为提交点；前端先显示进行中，成功后更新树，失败恢复旧状态。
- 删除优先进入系统废纸篓/回收站；能力不可用时必须由自定义对话框明确展示永久删除后果，用户二次确认后才调用永久删除。
- 文件监听事件合并并携带来源提示；应用自身操作通过操作令牌/短期事件登记去重，避免重复刷新和后续保存循环。
- 临时文件使用可识别且不与用户文件冲突的同目录命名；写入或替换失败先尝试删除。清理也失败时只在安全诊断日志记录脱敏引用，并在下一次应用启动执行有界重试；不得向 Toast 暴露绝对路径，也不得无限累积残件。

### 4.4 窗口、菜单与状态存储

- 启用 single-instance，确保一个进程协调多个工作区窗口；第二次启动或系统打开请求转交现有进程处理。
- 原生窗口标签统一使用不含路径的 `plainroot-window-N`，稳定 `workspaceId` 通过根会话映射到窗口标签；不把完整路径作为 label。之所以不直接把 workspaceId 编入不可变 label，是为了让“当前窗口替换目录”仍使用同一个原生窗口。窗口标题遵循“工作区 — 当前文件 — Plainroot”，第一阶段没有活动文档时显示“工作区 — Plainroot”。
- 原生菜单实现“文件、编辑、显示、窗口、帮助”顶层结构：阶段 1 启用打开文件夹、打开 Markdown 文件、新建窗口、关闭窗口、在文件管理器显示等已实现命令；后续命令保持禁用并具有明确状态，不绑定空操作。
- 最近工作区和根窗口会话由 Rust 仓储保存到 `appDataDir()/plainroot-state-v1.json`；数据包含 `schemaVersion: 1`，损坏或超过 8 MiB 的文件先备份为 `.corrupt-{timestamp}` 再回退默认，未知版本原样保留且禁止覆盖。
- 第一阶段每次打开其他目录都显示“当前窗口 / 新窗口 / 取消”三选项，不提供“记住选择”，也不持久化打开方式。后续只有在真实设置页可读取、修改并恢复为“每次询问”时，才能把 R14 的默认偏好与设置回退作为同一任务实现。
- 默认初始化数据：最近工作区空数组、根窗口会话空数组；初始化发生在应用首次启动或状态损坏回退时。
- 第一阶段不创建 SQLite、SQL、字典、远端权限、账号或服务端初始化数据。

## 10. 风险、假设与待确认项

### 10.1 风险

- Windows 原生选择器、回收站、Explorer 和菜单没有用户侧实机环境；CI 可覆盖真实 Windows 编译、命令和稳定 E2E，但不能完全替代人工可用性验收。缓解：T16 作为阶段门禁，T17 明确登记未验证人工项，最终跨平台阶段通过临时 Windows 设备、云桌面或受托测试取得证据。
- Windows WebView2 桌面 E2E 可能波动。缓解：构建/单元/命令集成为硬门禁；单用例最多重试一次并上传诊断；重复波动用例隔离并登记，核心链路不能静默放行。
- macOS 已安装并锁定 Rust 1.97.1，T1 构建链路已验证；Windows 工具链和同锁文件构建仍未验证，由 T16 建立 CI 后收口，当前不得把 macOS 结果外推为双平台通过。
- Windows 与 POSIX 的覆盖写语义不同；T10 已建立共享平台适配并在 macOS 执行故障注入，但 Windows `MoveFileExW` 替换/占用分支仍未在本机编译或实测，必须由 T16 的 `windows-latest` 收口，不能从 macOS 结果外推。
- 文件监听在不同平台产生的事件序列不同；T9 以最终磁盘一致为准并合并事件，不把单一事件序列写成跨平台契约。
- macOS App Store 沙箱的安全作用域书签会改变授权持久化方案。本阶段假设先做直接分发桌面应用；若确定 App Store 首发，需在发布计划前补充授权数据迁移设计。
- WebView 排版和系统字体存在平台差异；阶段 1 只验证壳和文件流程，R7/R32 视觉定稿由对应独立阶段计划承接。
- 单文件父目录可能很大或包含无关敏感文件。缓解：扫描前展示父目录授权范围和解析后的链接目标，允许取消；扫描渐进、可取消，且 Rust 只允许访问已确认 canonical root。
- 安全写临时文件可能在失败或崩溃时遗留。缓解：T10 已实现创建前日志登记、即时清理、仅文件名诊断、最多 32 项的启动重试，并限制为历史授权根内且重新验证无链接穿越的候选；日志异常时禁用安全写而不扩大删除范围。
- T10 清理日志的失效授权根预算风险已在 T15 关闭：不可再授权的记录会从活动日志剔除、磁盘残件保留，32 条失效记录后仍可执行新的安全写，并有回归测试锁定。T10 每次保存两次流式计算全文修订仍是当前防 TOCTOU 的安全取舍；只有大文档压力证据表明必要时才评估元数据快路径，不能先削弱第二次校验。
- `@wdio/tauri-service@1.2.0` 的 embedded provider 在 macOS 测试成功时仍错误诊断“未安装 tauri-driver”，结束会话时还会报告 mock store 清理告警；目前退出码与 3 个真实断言均正常。T16 若升级 service 或接入 CI，必须先复跑 E2E 和生产隔离检查；不得靠过滤 stderr 把真实失败吞掉。

### 10.2 已确认决策

- 使用用户已确认的 Tauri 2 + React + TypeScript 技术基线。
- 使用现有 NVM Node `v24.11.1`；`.nvmrc` 与 CI 固定该已验证补丁版本，`engines.node` 保留 Node 24 兼容范围。安全升级通过显式工具链变更完成，不在 CI 中静默漂移补丁版本。
- 单个 Markdown 文件的父目录作为工作区根，选中文件作为初始活动目标；该语义已随推荐方案获用户确认，不是本计划新增权限决策。第一阶段新增的范围展示与取消入口只是授权保护，不改变已确认语义。
- Windows 暂无用户侧实机，以 GitHub Actions `windows-latest` 取得编译、测试和稳定 E2E 证据，原生系统交互保持未验证直至后续取得人工证据。

### 10.3 非阻塞假设

- 第一阶段默认不跟随符号链接；显示/反馈但不跨越授权边界。
- 第一阶段 Rust JSON 状态仓储足够承载最近记录和根窗口会话；打开方式不持久化，SQLite/FTS5 由全文搜索独立计划再评估。
- R2 的编辑会话依赖项、R5 的完整状态机、R14 的全部页签保存检查按用户确认延后，不改变这些 R 项最终验收含义。

### 10.4 待确认项

- 无阻塞计划启动的问题。
- 非阻塞：正式应用 bundle identifier、图标和签名主体在首次可分发构建前确认；阶段 1 暂使用可替换的开发标识，但必须集中配置，不能散落硬编码。
- 非阻塞：Windows 人工验收的具体渠道可在最终跨平台阶段选择临时 Windows 设备、云桌面或受托测试者；在取得证据前 R1 不标记最终已完成。
